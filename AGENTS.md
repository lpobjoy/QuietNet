# Guide for agents (and people) working on QuietNet

Read this first. It is short, and it says what must stay true.

## What this is

A home network filter. Devices point their DNS at it; it records what they look up, blocks adverts, trackers and chosen services, and can cut live connections on a Raspberry Pi. An optional relay on a public host lets the owner reach it from outside.

- How it works, in full: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
- Every HTTP call: [docs/API.md](docs/API.md)
- Faults and gaps not yet fixed: [docs/KNOWN_ISSUES.md](docs/KNOWN_ISSUES.md)
- Testing: [docs/TESTING.md](docs/TESTING.md)

## Where things are

| File | What it holds |
| --- | --- |
| `server.py` | DNS filter, rules engine, dashboard web server, start-up. A map of its sections is near the top |
| `enforcer.py` | Cuts live connections: ARP steering and firewall rules. Linux only |
| `announcer.py` | A trial, off unless the owner switches it on: announces the Pi as an IPv6 DNS server beside the router's own. Builds whole network frames. Linux only |
| `cloud_agent.py` | The Pi's outbound link to the relay |
| `cloud/relay.py` | The relay: accounts, pairing, licences (and the owner's `licence` command line), the browser-to-Pi bridge. Deployed on its own; must not import the other programs |
| `static/index.html` | The dashboard. One file, served by both the Pi and the relay. Its script opens with notes for editors |
| `services.json`, `junk_domains.txt` | Data: blockable services and the built-in advert list |
| `install.sh` | The one-line installer for a Pi. Plain POSIX `sh` (dash, busybox ash, bash); everything in functions, only the last line runs; every value checked before use. Notes for editors at the top |
| `tests/` | One file per part. `test_quietnet.py` holds the shared helpers |
| `tests/test_installer.py` | Runs `install.sh` against stand-in commands; never real Docker, the network or the real `/etc` |

## Before you finish any change

```bash
python3 -m unittest discover tests
```

It takes about 85 seconds and needs nothing installed (`QUIETNET_BIG_ROWS=20000` in front makes the one big-history test quick while you work). It must end in `OK`. Run it as an ordinary user if you can: as an admin user on Linux, two shutdown tests are skipped.

## Rules

1. **Standard library only.** No third-party packages in the programs or the tests. A test enforces this.
2. **Every function and class has a docstring** that says what it does and, where it is not obvious, why. A test enforces this. Write for a reader who has not seen the rest of the file.
3. **Plain English, everywhere**: comments, error messages, the dashboard, the docs. Say "the router's hardware address", not "the gateway MAC". No jargon where an ordinary word will do. Messages shown to people should say what happened and what to do.
4. **Every behaviour change comes with a test**, named as a plain statement of the behaviour (`test_a_code_works_only_once`). One behaviour per test.
5. **Keep the docs true.** If you change a call, update `docs/API.md`. If you change how something works, update `docs/ARCHITECTURE.md`. If you fix or find a fault, update `docs/KNOWN_ISSUES.md`. Add a line to `CHANGELOG.md` under "Unreleased".
6. **Tests never touch the real network or the real data folder.** Use the stand-ins already in the test files. Never run the real `nft`, `iptables` or `sysctl` from a test.

## Security rules: do not loosen these without the owner's say-so

Each of these is the only thing standing between a hostile web page, or a stranger on the internet, and someone's home network. Each has tests.

- **The dashboard listens on `127.0.0.1` only and refuses any `Host` but localhost** (`Web.local_only`). Do not bind it to the home network or accept other host names.
- **Dashboard changes must arrive as JSON** (`Web.do_POST`). Do not accept form-encoded or plain-text bodies; that is the defence against forged cross-site requests.
- **Every relay handler that acts for a person starts with `user()` or `my_pi()`.** `my_pi()` is what keeps one account away from another's Pi.
- **Relayed API calls must carry the `X-QuietNet: 1` header** (`Relay.pi_request`).
- **Every value put into HTML is escaped**: `esc()` or `num()` in the dashboard, `html.escape()` in the relay. This includes ids and counts.
- **Nothing reaches a firewall rule unvalidated.** The address to steer comes from the live neighbour table and goes through `ipaddress.IPv4Address` (`live_cut_devices()`, and again in the enforcer); addresses to drop come only from parsed DNS answers.
- **The enforcer's firewall text must delete the old table before defining the new one** (`nft_ruleset`). Loading a table that exists adds to it, and stale drop rules cut devices off.
- **Both web servers send the frame, nosniff and referrer headers on every answer** (`end_headers`).
- **Wrong guesses at the relay are counted and capped** (`Throttle`), and pairing codes expire.
- **Request bodies are capped** (`MAX_BODY`) on both servers.

## Things that are easy to get wrong

- **Rules live in two places.** `S` (memory) and the database. Change both, holding `db_lock`. See `block()` for the pattern.
- **`decision()` runs for every lookup.** Keep it free of database calls and anything slow.
- **The order of checks in `decision()` is behaviour people rely on.** It is tabulated in `docs/ARCHITECTURE.md`; change the two together.
- **The dashboard page is edited by the relay with a plain text replace** on the opening `head` and `body` tags. Keep exactly one of each, lower case, no attributes.
- **The three looks (themes) must each stay complete.** The dashboard's style sheet and the relay's `RELAY_CSS` set every colour and size name for each look under `[data-theme="..."]`, with Calm as the root default (the font stacks `--font-body` and `--font-mono` are shared from the root on purpose). A new colour or size name goes into all three looks (and Calm's and Household's dark sets), the markup stays free of fixed colours and inline styles, and nothing is loaded from other websites: no font files, `@import` or outside addresses. Theme names are checked against `calm`, `household` and `control` wherever the `qn_theme` cookie is read.
- **"IPv6 is off on your hub" is shown only on evidence** (`ipv6_dns_view()`, `hub_off`): a full hour of listening with no router heard, this computer's own IPv6 working on its home network card for that whole hour (`ipv6_on_card()`: with it switched off the listener runs but hears nothing), no public IPv6 address, no IPv6 DNS server but this computer being named by anyone (a router with no IPv6 internet can still name its own), and a recent look. A listener that never started, a restart, or anything unknown must never read as "off". Keep the steady timer (`time.monotonic()`); a Pi's clock jumps.
- **The IPv6 DNS announcement trial must stay harmless** (`announcer.py`). Off unless the owner switches it on; while off, nothing is sent and no socket is opened (the one exception: a goodbye that could not be sent when it was switched off is tried again for up to ten minutes). Its message has a router lifetime of 0, no address range, no route, no DHCPv6 flags and nothing but the DNS part, and names only the address it is sent from (`build_dns_announcement()` refuses anything else). It is sent only while QuietNet answers a test lookup at that very address on port 53, and never while there is a reason to hold back (`announce_hold_reason()` in `server.py`: a Wi-Fi range extender is known, whose devices would be judged under one device's rules over IPv6; or the Pi could be the only IPv6 DNS server named while a router hands out IPv6, so that a goodbye would drop Android phones off Wi-Fi; or that is not yet known) or while the card has two link-local addresses. Devices are told to stop (lifetime 0) when it is switched off, on a clean stop, and when it holds back; an address is forgotten only when a goodbye naming it really left or its ten minutes have run out, and the log never says devices were told when no goodbye left. `main()` starts it last, inside the block whose clean-up says goodbye, so a start-up that fails announces nothing. The switch's wording must go on saying that devices never set up to use QuietNet may start using it and get whole-house rules. Each of these has tests in `tests/test_announcer.py`. It can't beat the router's own announcement, so nothing may treat a device as covered because of it: the "Can bypass over IPv6" labels and `hub_off` must not look at it.
- **An IPv6 address built from a hardware address is a hint, never proof** (`eui64_mac()`). Any device can make one. Only the neighbour table decides which device an address belongs to, and so whose rules apply.
- **A lookup must never run tools or wait long.** A lookup from an unknown IPv6 address only sets a flag for the IPv6 watcher and waits a fraction of a second at most (`matched_ipv6_device()`), outside `decision()`.
- **History queries must use an index.** `queries` can hold a month of a household's lookups. A test checks the query plans.
- **One device is one hardware address, and nothing is merged automatically.** The history is filed against the device (`queries.device`), found on a lookup by one dictionary lookup in `S.addr_device`, never by a database call. Only the neighbour tables put an address in that map (`note_ipv4_addresses()`, `note_ipv6_addresses()`), and only when it was confirmed just now: a stale IPv4 entry may belong to a device that has left. One hardware address at two live addresses, or a range extender's, must never join two devices. `address_use` is for the history and for showing the owner; it never decides whose rules apply and it never steers.
- **Names, groups and rules are held against the device, never against an address.** Scopes are `all`, `group:<id>` and `dev:<number>`; `S.given`, `S.dev_group` and `S.enforced` are keyed by device number. `device:<address>` is only how a request from an older page names a device (`stored_scope()` turns it into the device listed there) and how an older database not yet moved keeps its rules. Nothing is moved when an address changes: `S.addr_rules` says whose rules a lookup from each address gets (`rebuild_rule_map()`), found with one dictionary lookup in `answer_query()`, before `decision()`. It is wider than `S.addr_device` on purpose (a stale or vanished entry still names the device last heard from an address, so an idle phone's first lookup gets its rules), but must never give one device another's: a different hardware address at the address wins at the next look; a hardware address at two live addresses keeps its rules at the first only; a DHCP request (`note_dhcp()`) may pause the old device's rules or give the address a device QuietNet already knows, but never overrules what the table confirmed, never makes a device and never steers, and it is withdrawn as soon as the device that sent it asks for another address or is confirmed by a look at another address (a device refused its old number must not leave its rules on whoever has that number). The enforcer steers only where the live neighbour table, read for that tick, lists the device's own hardware address at the address the looks hold its rules at (`S.rules4`; `live_cut_devices()`), on a fresh entry or a stale one: a steered device's entry is stale most of the time, because the Pi sends it nothing between its lookups, and dropping it then would hand it back to the router and let a bedtime that starts cut nothing. A stale entry is passed over when that hardware address is fresh at another address; `address_use` and DHCP requests never come into it; a number behind a range extender is steered only on a fresh entry. Do not put a "fresh only" test back without a way to keep a steered device's entry fresh. A new device at the number of a device with rules, or a device seen at a number that rules are held against, is given those rules as well as its own and the owner is asked (`S.provisional`). Whether a number changed hands comes from the looks themselves (`S.had4`), never from `address_use`, and never while the earlier device is listed anywhere in the table, even on a stale entry: an old address record must not hold a newcomer to the rules of a device that has only moved. A newcomer that takes the number of a follower follows the device that one follows, never the follower. Only the owner's "yes" joins two devices (`merge_devices()`): every switch, block and schedule either carried is kept, and since a device has one name and one group, when both had one the owner is told which gave way.
- **Merge and Separate are shown before they are done, and never happen on the first ask.** `POST /api/merge` and `POST /api/separate` answer a request that carries no `seen` with a preview only (`merge_preview()`, `separate_preview()`): what would apply to each hardware address afterwards, in plain words. Only a request that sends the preview's marker back is carried out (`merge_by_hand()`, `separate_by_hand()`), and only while the preview would still read the same; otherwise `409` and nothing is done. Keep it that way: no default for "do the rules go with it?", no confirming with the Enter key on the page (`askPreview()`), and no path that merges without the marker except the older `POST /api/move-rules`, kept for pages written before. A separated hardware address keeps no history (it stays with the device it was merged into) and is remembered as a different device (`S.not_same`), so it is not at once held to the other's rules again. But Separate must never shed rules that are being held to a device: when the device is itself held to a third device's rules (`S.provisional`), the separated one is held to them too and the preview says so. A preview must not promise an undo that does not exist: a merge with a device known only by its number can't be undone with Separate, and the preview's last note says that. A number behind a Wi-Fi range extender is never merged, and that is decided from what is remembered (`S.behind_extender`), never from a warning worked out at the last look, which is gone while the device behind the extender sleeps. The marker is worked out with `steady_label()`, so the address an unnamed device is shown by, which moves from look to look, never makes a preview out of date; anything that changes what would be done must stay in it. The dashboard knows a card by the device's number (`keyOf()`), never by an address alone, and never asks to clear history without naming a device.
- **An older household's database is moved to the device tables after start-up, never in `init_db()`** (`move_to_devices()`, from the device keeper, once the filter and the enforcer are running). Building the index on a big history is slow, and a slow or failing start would leave the house without DNS. The move keeps a copy first, is one transaction (the devices, then the names, groups and rules: `build_devices()`, `move_rules_to_devices()`), and on any error rolls back and leaves QuietNet running on the old tables (`S.devices_ready` stays false; every code path must still work then, with rules under addresses and the pause in `pause_old_rules()`). The move of rules changes the database only, never `S`, until it has been saved. It must never silently drop or newly apply an internet switch, a schedule or a cut: rules go to a device only on certain evidence (`device_mac`), otherwise they stay with their number. When one device had rules under two numbers, the older QuietNet applied the set kept under the number the device was NOT at; that set stays with the device, and every other set that asks for more is set aside for the owner to choose (`rule_conflict`). A set that is set aside applies to no lookup and is given to no device until the owner has chosen (`S.set_aside`), so the device has exactly the rules it had the day before. It waits up to two minutes for this computer to know its own address, since it decides once which old history is this computer's and the router's. The copy holds the household's history, so it must not outlive it: `forget_old_copy()` deletes it at 30 days and whenever everyone's history is forgotten.
- **`cloud/relay.py` is deployed without the other programs.** It cannot import them.
- **Licence code stays on the relay and never answers 401.** It must never reach the Pi's blocking (`decision()`, the enforcer, the internet switches). A licence refusal is `402` or `403`, never `401`, which today's Pis take to mean "unpaired" and delete their token. Every licence decision reads `licence_state()`. Every refusal goes through `licence_gate()` (`pi_request`, `POST /pis/new`, `agent_pair`); the home page only reads `gate_on()` and `licence_state()` to decide what to show. The two rescue calls must keep working in every licence state.
- **Python 3.9 must still work** for the programs: the macOS launcher prefers the Python that Apple supplies. Avoid newer syntax such as `match` or `X | Y` type hints at run time.

## Working method

- Work on a branch and open a pull request; do not push to `main`.
- Keep a change to one concern where you can.
- The enforcer and the containers cannot be fully tested here. If you change either, say so in the pull request and list what needs checking on a real Pi (`docs/TESTING.md` has the manual steps).
